# Data tables for Minecraft 26.3 (protocol 777)

These JSON files are compiled into the `paper-data` crate by its build script.

| File | Contents |
| --- | --- |
| `version.json` | version name, protocol and data versions |
| `packets.json` | packet names per state and direction; the array index is the packet id |
| `registries.json` | built-in registries; the array index is the protocol id |
| `blocks.json` | blocks in registry order with their properties and state id ranges |
| `block_states.json` | per block state: light emission, light opacity, flags |
| `items.json` | items in registry order with stack size and the block they place |
| `synced_registries.json` | registries sent to clients during configuration, in send order |
| `tags.json` | tags sent to clients, resolved to numeric ids |
| `dimension_types.json` | the vanilla dimension type definitions |
| `feature_flags.json` | feature flags enabled by default |

## Provenance

Nothing here was produced by running Mojang's server. The current files are an interim
set generated by `tools/datagen/interim_data.py` from:

* the 26.3 server jar read as a zip archive (`data/minecraft/**`: synchronised registry
  entries, tags, dimension types) and its class files disassembled with `javap` (registry
  keys, the list of synchronised registries, command argument type order);
* [misode/mcmeta](https://github.com/misode/mcmeta) `26.3-summary` (MIT): block property
  names and value order, and the name set of every registry, used as a cross-check;
* [Pumpkin-MC/Pumpkin](https://github.com/Pumpkin-MC/Pumpkin) `assets/` (GPL-3.0): numeric
  registry orders and per-state physical block properties.

Checks performed while generating: every registry's name set equals mcmeta's; for all
1286 blocks the state count, first state id and default state derived from mcmeta's
property definitions agree with the reference ids (35723 states in total); every tag
entry resolves.

A second, independent extraction that derives the numeric ids directly from the server
jar's bytecode is in progress and will replace or confirm these files.
