# Data tables for Minecraft 26.3 (protocol 777)

These JSON files are compiled into the `paper-data` crate by its build script.

| File | Contents |
| --- | --- |
| `version.json` | version name, protocol and data versions |
| `packets.json` | packet names per state and direction; the array index is the packet id |
| `registries.json` | 95 built-in registries plus the entity data serializers; the array index is the protocol id |
| `blocks.json` | blocks in registry order with their properties and state id ranges |
| `block_states.json` | per block state: light emission, light opacity, flags |
| `items.json` | items in registry order with stack size and the block they place |
| `synced_registries.json` | registries sent to clients during configuration, in send order |
| `tags.json` | tags sent to clients, resolved to numeric ids |
| `dimension_types.json` | the vanilla dimension type definitions |
| `feature_flags.json` | feature flags enabled by default |
| `block_behaviour.json` | per block state: sturdy faces, legacy solid, redstone conductor, comparator output, piston reaction, full collision faces, note block instrument |
| `block_physics.json` | per block state: collision shapes and behaviour flags; per block: loot table, friction, speed and jump factors; block entity types |
| `item_components.json` | default components of items that behave differently (durability, food, tools, weapons, attributes, equipment slots, fuel) |
| `entities.json` | entity types: size, eye height, category, attributes, health, experience, spawn rules, sounds |
| `entity_data.json` | the entity metadata layout (field index and serializer) of each entity type |
| `game_rules.json` | game rules with their defaults (and bounds for integer rules) |
| `legacy.json` | the pre-1.13 numeric ids (`id:data`) as 26.3 block states and items, for the plugin host's legacy materials |
| `worldgen/multi_noise_biome_tree.json.gz` | the multi-noise biome parameter R-trees of the `overworld` and `nether` presets (embedded by `paper-worldgen`) |
| `worldgen/block_physics.bin.gz` | per block state: physical flags and sturdy faces that world generation features test (embedded by `paper-worldgen`) |

## Provenance

Generated by `tools/datagen/extract.py`; see `tools/datagen/README.md` for the
exact inputs, the method and the full list of checks
(`tools/datagen/reports/26.3-validation.json`). In short:

* Numeric ids (packets, registries, block states, items) are derived from the
  26.3 server jar's bytecode by a symbolic evaluator written for this purpose.
  The jar is read as data; none of its code is run.
* Block property names, value order and default states, and item stack sizes,
  come from [misode/mcmeta](https://github.com/misode/mcmeta) `26.3-summary`.
* Light opacity and the collision, full-cube and fluid flags in
  `block_states.json` come from the `assets/blocks.json` file of
  [Pumpkin-MC/Pumpkin](https://github.com/Pumpkin-MC/Pumpkin). Pumpkin's code is
  GPL-3.0; its `assets/NOTICE.md` states that these extracted files are derived
  from Minecraft and are not covered by Pumpkin's licence.
* `block_behaviour.json` is derived from the same Pumpkin file by
  `tools/datagen/physics.py`, which first checks that Pumpkin's block list and
  state id ranges are identical to `blocks.json`.
* `block_physics.json`, `item_components.json`, `entities.json`,
  `entity_data.json` and `game_rules.json` are derived from Pumpkin's
  `assets/` (`blocks.json`, `items.json`, `entities.json`, `tracked_data.json`,
  `game_rules.json`) by `tools/datagen/pumpkin_extra.py`, which checks item ids
  and block state ids against `items.json` / `blocks.json` and game rule names
  against the `minecraft:game_rule` registry. The same licence note applies.
* Synchronised registry entries, tags and dimension types are read from the
  `data/minecraft/**` files inside the jar.
* `worldgen/multi_noise_biome_tree.json.gz` is `assets/multi_noise_biome_tree.json` of
  [Pumpkin-MC/Pumpkin](https://github.com/Pumpkin-MC/Pumpkin) at commit e9dc12e9, gzipped
  (uncompressed SHA-256 `a2e45033…c8a595`). Vanilla builds these trees in code
  (`OverworldBiomeBuilder`, the nether preset), not from data; Pumpkin extracted them from
  26.3 in vanilla's own R-tree layout, so searching them visits leaves in vanilla's order.
  Pumpkin's `assets/NOTICE.md` treats data extracted from Minecraft as Mojang's, not covered
  by Pumpkin's licence.
* `worldgen/block_physics.bin.gz` holds, for every block state id in order, the
  `state_flags` (u16, little endian: air, burnable, tool required, sided transparency,
  replaceable, liquid, legacy solid, full cube, solid block, random ticks, solid render, can
  occlude, analog output) and `side_flags` (u8: sturdy down/up/north/south/west/east, center
  sturdy down/up) of `assets/blocks.json` of
  [Pumpkin-MC/Pumpkin](https://github.com/Pumpkin-MC/Pumpkin) at commit e9dc12e9, gzipped.
  Vanilla computes these from block shapes in code. Rebuild it with
  `python3 -I crates/paper-worldgen/scripts/block_physics.py <pumpkin>/assets/blocks.json
  data/26.3/blocks.json data/26.3/worldgen/block_physics.bin.gz`, which also checks that every
  state id belongs to the same block in both files.

* `legacy.json` is built by `tools/datagen/legacy.py` from `data/pc/common/legacy.json` of
  [PrismarineJS/minecraft-data](https://github.com/PrismarineJS/minecraft-data) (MIT
  licence), which maps 1.12 ids to 1.13 names. The script renames what changed after 1.13
  (signs, the smooth stone slab, three dyes, dirt paths, short grass, turtle scutes, the
  zombified piglin egg; wall sides became `none`/`low`) and checks every block, property,
  value and item against `blocks.json` and `items.json`.

Every registry was checked for an identical name set against mcmeta, and every
order that an independent source covers (packets, block states, 22 registries)
was checked against it. `python3 -I tools/datagen/check.py data/26.3` re-verifies
the internal consistency of these files.
